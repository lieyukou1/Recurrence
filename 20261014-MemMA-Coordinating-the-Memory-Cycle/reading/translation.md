## Abstract / 摘要

**EN.** Memory-augmented LLM agents maintain external memory banks to support long-horizon interaction, yet most existing systems treat construction, retrieval, and utilization as isolated subroutines. This creates two coupled challenges: *strategic blindness* on the forward path of the memory cycle, where construction and retrieval are driven by local heuristics rather than explicit strategic reasoning, and *sparse, delayed supervision* on the backward path, where downstream failures rarely translate into direct repairs of the memory bank. To address these challenges, we propose MemMA, a plug-and-play multi-agent framework that coordinates the memory cycle along both the forward and backward paths. On the forward path, a Meta-Thinker produces structured guidance that steers a Memory Manager during construction and directs a Query Reasoner during retrieval. On the backward path, MemMA introduces in-situ self-evolving memory construction, which synthesizes probe QA pairs, verifies the current memory, and converts failures into repair actions before the memory is finalized. Extensive experiments on LoCoMo show that MemMA consistently outperforms existing baselines across multiple LLM backbones and improves three different storage backends in a plug-and-play manner. Our code is publicly available at https://github.com/ventr1c/memma.

**中.** 记忆增强的 LLM agent 会维护外部记忆库以支撑长程交互，但现有大多数系统把 construction（构建）、retrieval（检索）与 utilization（利用）当作**彼此孤立的子程序**。这带来两个相互耦合的挑战：记忆周期**前向路径**上的 *strategic blindness*（战略盲区）——构建与检索由**局部启发式**而非**显式战略推理**驱动；以及**后向路径**上的 *sparse, delayed supervision*（稀疏且延迟的监督）——下游的失败很少能转化为对记忆库的**直接修复**。为应对这两点，我们提出 **MemMA**：一个即插即用的多智能体框架，沿前向与后向两条路径**协同记忆周期**。在前向路径上，一个 **Meta-Thinker** 产出结构化指导，在构建阶段引导 **Memory Manager**、在检索阶段引导 **Query Reasoner**。在后向路径上，MemMA 引入 **in-situ self-evolving memory construction**（就地自演化记忆构建）：合成探针 QA 对（probe QA pairs）、对当前记忆做验证，并在记忆**定稿之前**把失败转成修复动作。在 LoCoMo 上的大量实验表明，MemMA 在多种 LLM 后端上一致优于现有基线，并以即插即用方式改善**三种不同的存储后端**。代码公开于 https://github.com/ventr1c/memma 。

## 1. Introduction / 引言

**EN.** Large language models (LLMs) are evolving from episodic chatbots into persistent agentic systems that execute complex workflows over days or weeks. In such settings, agents receive a continuous stream of observations—user constraints, tool outputs, and environmental feedback—whose consequences unfold over long horizons. This shift makes *controllable, long-term memory* a first-class requirement: relying solely on ephemeral context windows is insufficient, as they are computationally expensive and prone to attention dilution. To maintain coherence over time, agents must actively manage an external memory bank, deciding what to retain and how to retrieve it under uncertainty.

**中.** 大语言模型（LLM）正从**回合制聊天机器人**演化为能连跑数天甚至数周的**持续 agent 系统**。在这类场景中，agent 接收连续的观察流——用户约束、工具输出与环境反馈——其后果在**长时程**上逐步展开。这一转变让**可控的长期记忆**成为**一等需求**：仅依赖易失的上下文窗口是不够的，因为它计算昂贵且容易被注意力稀释。要在时间上保持连贯，agent 必须**主动管理**一个外部记忆库，自行决定保留什么、以及在不确定条件下如何检索。

**EN.** Effective memory, however, is not merely a storage utility; it is a closed-loop dynamic, conceptualized as the *memory cycle effect* (Zhang et al., 2025b). This cycle has three coupled phases: *construction*, *retrieval*, and *utilization*. Construction determines what information enters the memory bank and how it is organized; retrieval determines what stored information is surfaced as evidence; and utilization reveals whether the retrieved evidence is sufficient for downstream reasoning. This coupling implies that optimizing these stages in isolation is fundamentally suboptimal: a retrieval failure may stem from a much earlier construction error, while utilization outcomes should ideally feed back to improve future memory decisions. Despite this intrinsic dependency, most existing memory-augmented agents (Chhikara et al., 2025; Fang et al., 2025; Xu et al., 2025; Yan et al., 2025; Zhou et al., 2025) still treat memory operations as isolated, reactive subroutines, overlooking the coupling between stages. To leverage the memory cycle effect, two technical challenges must be addressed (Fig. 1).

**中.** 然而，有效的记忆**不只是**一种存储工具；它是一个**闭环动态**，被概念化为 *memory cycle effect*（记忆周期效应，Zhang et al., 2025b）。这个循环有三个耦合阶段：*construction*（构建）、*retrieval*（检索）与 *utilization*（利用）。构建决定哪些信息进入记忆库、以及如何组织；检索决定哪些已存信息被作为证据**浮出**；利用则揭示所浮出的证据是否**足以支撑下游推理**。这种耦合意味着**孤立地**优化各个阶段在根本上是次优的：一次检索失败可能源于**早得多的一次构建错误**；而利用的结果，理想情况下应当**回馈**以改进未来的记忆决策。尽管存在这种内在依赖，现有大多数记忆增强 agent（Chhikara et al., 2025; Fang et al., 2025; Xu et al., 2025; Yan et al., 2025; Zhou et al., 2025）仍把记忆操作当作**孤立的、反应式的**子程序，忽视了阶段之间的耦合。要真正利用记忆周期效应，必须解决两个技术挑战（图 1）。

**EN.** First, on the *forward path* of the memory cycle, current systems often suffer from *strategic blindness*: they possess the mechanisms to edit memory and issue retrieval queries, yet lack explicit *meta-cognition* to coordinate these actions toward downstream question answering. As our preliminary analysis shows (Sec. 3.3), this manifests as two pathologies: (i) *Myopic Construction*, where the agent accumulates or overwrites conflicting facts without resolution; and (ii) *Aimless Retrieval*, where the agent performs shallow or repetitive searches without narrowing the true information gap. These failures suggest that *effective forward-path memory behavior requires explicit coordination between construction and retrieval, rather than isolated, short-sighted decisions*.

**中.** 第一，在记忆周期的**前向路径**上，现有系统常常受困于 *strategic blindness*（战略盲区）：它们**具备**编辑记忆和发出检索查询的机制，却缺乏显式的 *meta-cognition*（元认知）来把这些动作**协调**到面向下游问答的目标上。如我们的预分析所示（§3.3），它表现为两种病症：(i) *Myopic Construction*（短视构建）——agent 不断累积或覆盖**相互冲突**的事实而不加解决；(ii) *Aimless Retrieval*（无的放矢的检索）——agent 做浅层或重复的检索，却**收窄不了真正的信息差**。这些失败说明：*有效的前向路径记忆行为，要求构建与检索之间存在显式协调，而不是孤立、短视的决策*。

**EN.** Second, on the *backward path* of the memory cycle, feedback from utilization to construction is typically *sparse and delayed*. Whether a memory-writing decision is useful may become clear only much later, when the agent fails a downstream question. This makes credit assignment difficult: when an answer is wrong, it is hard to identify which earlier construction decision caused the failure, allowing early omissions and unresolved conflicts to persist in the memory bank and affect later updates. Although recent methods use reflection or experiential learning to improve agent behavior (Shinn et al., 2023; Zhao et al., 2024; Zhang et al., 2026), downstream failures are still rarely converted into direct signals for repairing the memory bank itself.

**中.** 第二，在记忆周期的**后向路径**上，从利用到构建的反馈通常是 *sparse and delayed*（稀疏且延迟的）。一个记忆写入决策是否有用，可能**很久之后**才变得清楚——即当 agent 在某个下游问题上失败之时。这让**信用分配（credit assignment）**变得困难：当答案错了，很难认定是**早先哪一次构建决策**导致了失败，于是早期的遗漏与未解决的冲突就**留在**记忆库里、并影响后续更新。尽管近期方法用反思或经验学习来改进 agent 行为（Shinn et al., 2023; Zhao et al., 2024; Zhang et al., 2026），下游失败**仍然很少**被转化为**直接修复记忆库本身**的信号。

**EN.** To address these challenges, we propose MemMA (**Mem**ory Cycle **M**ulti-**A**gent Coordination), a plug-and-play multi-agent framework that coordinates the memory cycle along its forward and backward paths. Specifically, for the *forward path*, MemMA separates strategic reasoning from low-level execution through a planner-worker architecture: a Meta-Thinker produces structured guidance that steers a Memory Manager during construction (what to retain, consolidate, or resolve), thereby mitigating *Myopic Construction*, and directs a Query Reasoner during retrieval by diagnosing missing evidence and how to retrieve it, replacing one-shot search with diagnosis-guided iterative refinement and thereby mitigating *Aimless Retrieval*. For the *backward path*, MemMA introduces in-situ self-evolving memory construction: after each session, the system synthesizes probe QA pairs, verifies the current memory against them, and converts failures into repair actions on the memory bank through evidence-grounded critique and semantic consolidation, before the memory is committed for future use. This directly addresses *sparse and delayed supervision* by turning downstream failures into immediate, localized repair signals for the current memory state, before flawed memories propagate into future memory updates.

**中.** 为应对这些挑战，我们提出 **MemMA**（**Mem**ory Cycle **M**ulti-**A**gent Coordination）。具体地，对于**前向路径**，MemMA 通过 **planner-worker（规划者—执行者）架构**把**战略推理**与**低层执行**分离：一个 **Meta-Thinker** 产出结构化指导，在构建期引导 Memory Manager（该保留什么、整合什么、解决什么），从而缓解 *Myopic Construction*；并在检索期通过**诊断缺失证据及其检索方式**来引导 Query Reasoner，用"诊断引导的迭代细化"取代一次性检索，从而缓解 *Aimless Retrieval*。对于**后向路径**，MemMA 引入就地自演化记忆构建：每个 session 之后，系统合成探针 QA 对、据此验证当前记忆，并通过**证据锚定的批判（evidence-grounded critique）**与**语义整合（semantic consolidation）**把失败转成对记忆库的修复动作——**在记忆被提交供未来使用之前**。这通过把下游失败转化为对**当前记忆状态**的**即时、局部**修复信号，直接应对 *sparse and delayed supervision*，避免有缺陷的记忆传播进后续的记忆更新。

**EN.** Our contributions are: (i) *Analysis*. We identify two technical challenges in leveraging the memory cycle effect: *strategic blindness* on the forward path and *sparse, delayed feedback* on the backward path, and provide empirical evidence through a controlled preliminary study (Sec. 3.3). (ii) *Framework*. We propose MemMA, a plug-and-play multi-agent framework that coordinates the memory cycle along both its forward and backward paths, combining reasoning-aware coordination for construction and iterative retrieval with in-situ self-evolving memory construction for backward repair. (iii) *Experiments*. MemMA outperforms existing baselines on LoCoMo across multiple LLM backbones, and consistently improves three storage backends as a plug-and-play module.

**中.** 我们的贡献是：(i) *分析*。我们识别出利用记忆周期效应中的两个技术挑战——前向路径的 *strategic blindness* 与后向路径的 *sparse, delayed feedback*——并通过一个受控预实验（§3.3）给出实证。(ii) *框架*。我们提出 MemMA：一个即插即用的多智能体框架，沿前向与后向两条路径协同记忆周期，把"面向构建与迭代检索的推理感知协调"与"用于后向修复的就地自演化记忆构建"结合起来。(iii) *实验*。MemMA 在 LoCoMo 上跨多种 LLM 后端优于现有基线，并作为即插即用模块一致地改善三种存储后端。

## 2. Related Work / 相关工作

**EN.** **Memory-Augmented LLM Agents.** External memory has become a core component of LLM agents that operate over long horizons. Prior work improves long-term memory from several directions, including memory architecture (Packer et al., 2023; Zhong et al., 2024), memory organization and consolidation (Xu et al., 2025; Fang et al., 2025), and memory retrieval (Du et al., 2025). These methods substantially improve individual stages of the memory pipeline, but they primarily optimize storage, organization, or retrieval in isolation. Our work is inherently different from existing work: MemMA jointly coordinates memory construction and iterative retrieval, and converts utilization failures into direct repair signals for the memory bank. Full version is in Appendix A.

**中.** **记忆增强的 LLM agent。** 外部记忆已成为长时程 LLM agent 的核心组件。先前工作从几个方向改进长期记忆，包括记忆架构（Packer et al., 2023; Zhong et al., 2024）、记忆组织与整合（Xu et al., 2025; Fang et al., 2025）、以及记忆检索（Du et al., 2025）。这些方法大幅改进了记忆流水线的**单个阶段**，但它们主要**孤立地**优化存储、组织或检索。我们的工作与它们有本质不同：MemMA **联合**协调记忆构建与迭代检索，并把利用阶段的失败转成对记忆库的**直接修复信号**。完整版见附录 A。

## 3. Preliminaries and Motivation / 预备知识与动机

### 3.1 Problem Setting / 问题设定

**EN.** **Task Setup.** We consider a long-horizon conversational setting in which an agent processes a stream of dialogue chunks C={c_1,…,c_T} over time. The stream is further organized into sessions S={s_1,…,s_N}, where each session s_r consists of one or more consecutive chunks corresponding to a coherent interaction episode. At each step t, the agent maintains an external memory bank M_t composed of structured entries (e.g., text, timestamp, source, and speaker metadata), which is updated as new conversational information arrives. After processing the full stream C, the agent is evaluated on a set of questions Q. For each query q∈ Q, it retrieves evidence E(q) from M_T and outputs an answer ŷ(q). Our goal is to design an agent π that maximizes answer accuracy by jointly improving memory construction and retrieval.

**中.** **任务设定。** 我们考虑一个**长时程对话**场景：agent 随时间处理一个对话块（dialogue chunk）流 C={c_1,…,c_T}。该流进一步被组织为**会话** S={s_1,…,s_N}，每个会话 s_r 由一个或多个**连续的**块组成，对应一段连贯的交互片段。每一步 t，agent 维护一个外部记忆库 M_t，由结构化条目构成（如文本、时间戳、来源、说话人元数据），并随新的对话信息到达而更新。处理完整个流 C 后，agent 在一组问题 Q 上被评测。对每个查询 q∈ Q，它从 M_T 检索证据 E(q) 并输出答案 ŷ(q)。我们的目标是设计一个 agent π，通过**联合改进**记忆构建与检索来最大化答案准确率。

**EN.** **Challenges.** This setting is challenging because success depends on both memory construction and memory retrieval. During *construction*, the agent must decide what to write, update, merge, or discard when a new chunk arrives. During *retrieval and answering*, it must identify the right evidence from memory under ambiguity, temporal dependencies, and incomplete or underspecified initial queries. The challenge is therefore not merely to improve answer generation, but to maintain a useful memory bank and retrieve the right evidence under bounded memory and retrieval budgets.

**中.** **挑战。** 该场景之所以困难，是因为成功同时取决于记忆构建与记忆检索。在*构建*期间，新块到达时 agent 必须决定**写、更新、合并还是丢弃**什么。在*检索与作答*期间，它必须在**歧义、时间依赖、以及初始查询不完整/欠指定**的条件下，从记忆中找出正确的证据。因此挑战**不只是**改进答案生成，而是要在**有界的记忆与检索预算**下维护一个**有用的记忆库**并检索到**正确的证据**。

### 3.2 Memory Cycle Effect as a Design Lens / 以记忆周期效应作为设计透镜

**EN.** The above challenges suggest that long-term memory should not be viewed as a linear pipeline of isolated modules. Instead, we adopt the *memory cycle effect* (Zhang et al., 2025b) as a design lens for analyzing long-term memory systems. Under this view, memory forms a closed loop with three tightly coupled phases: *construction*, *retrieval*, and *utilization*. Construction determines what information enters the memory bank and how it is organized; retrieval determines what stored information is surfaced as evidence; and utilization reveals whether the retrieved evidence is sufficient for downstream answering.

**中.** 上述挑战表明，长期记忆**不应**被看作孤立模块的**线性流水线**。我们改用 *memory cycle effect*（Zhang et al., 2025b）作为分析长期记忆系统的**设计透镜**。在这一视角下，记忆形成一个**闭环**，包含三个**紧耦合**阶段：*construction*、*retrieval*、*utilization*。构建决定哪些信息进入记忆库、如何组织；检索决定哪些已存信息被作为证据浮出；利用则揭示浮出的证据**是否足以支撑下游作答**。

**EN.** This perspective highlights two dependencies. First, there is a *forward dependency*: construction constrains retrieval, and retrieval in turn constrains utilization. A poorly constructed memory bank may omit important details, retain redundant entries, or leave conflicts unresolved, all of which degrade downstream retrieval quality. Second, there is a *backward dependency*: utilization outcomes expose deficiencies in upstream memory operations, since answering failures may stem from earlier storage omissions, unresolved contradictions, or poorly targeted retrieval. As a result, the utility of memory operations is often sparse and delayed, making isolated optimization of memory modules fundamentally suboptimal.

**中.** 这一视角凸显两种依赖。第一，存在**前向依赖（forward dependency）**：构建约束检索，检索又约束利用。构建得很差的记忆库会**漏掉重要细节、保留冗余条目、或让冲突悬而未决**——这些都会拉低下游检索质量。第二，存在**后向依赖（backward dependency）**：利用的结果会**暴露**上游记忆操作的缺陷，因为作答失败可能源于**更早的存储遗漏、未解决的矛盾、或定位不准的检索**。其结果是，记忆操作的效用往往**稀疏且延迟**，使得对记忆模块的孤立优化在根本上是**次优**的。

**EN.** Together, these dependencies suggest that long-term memory should be studied as a coupled cycle rather than independent storage and retrieval components. This motivates the need for mechanisms that *explicitly coordinate forward memory execution* and *propagate utilization feedback backward* to improve future memory decisions.

**中.** 综合来看，这些依赖表明：长期记忆应当被当作一个**耦合循环**来研究，而不是独立的存储与检索组件。这就**要求**有机制去*显式协调前向的记忆执行*、并*把利用反馈向后传播*以改进未来的记忆决策。

### 3.3 Motivating Analysis: Strategic Blindness / 动机分析：战略盲区

**EN.** The analysis above motivates coordination across the memory cycle, but do existing active memory agents achieve this in practice? Recent agents (Fang et al., 2025; Xu et al., 2025) have moved beyond fully passive memory by introducing active memory updates or iterative retrieval. However, most still operate in a largely reactive manner: they trigger operations based on local context or immediate similarity signals rather than an explicit global strategy. We characterize this limitation as *strategic blindness*: the agent has the *hands* to edit memory and issue retrieval queries, but lacks the *brain* to coordinate these actions across the full memory cycle. This manifests as: (i) *Myopic Construction*: construction decisions are driven by local context rather than downstream utility. The agent indiscriminately appends, overwrites, or ignores information, leaving redundancy and conflicts unresolved. (ii) *Aimless Retrieval*: when the initial query is incomplete or semantically mismatched with stored memory, one-shot retrieval or shallow rewrites fail to surface the required evidence. Without strategic guidance, successive queries do not narrow the information gap.

**中.** 上述分析表明需要跨记忆周期的协调，但现有的**主动**记忆 agent 在实践中做到了吗？近期 agent（Fang et al., 2025; Xu et al., 2025）通过引入主动记忆更新或迭代检索，已超越完全被动的记忆。然而它们大多仍以**反应式（reactive）**方式运作：依据**局部上下文**或**即时相似度信号**触发操作，而非遵循**显式的全局战略**。我们把这一局限刻画为 *strategic blindness*（战略盲区）：agent 有编辑记忆、发出检索查询的**手**，却没有跨整个记忆周期协调这些动作的**脑**。它表现为：(i) *Myopic Construction*——构建决策由局部上下文而非下游效用驱动，agent 无差别地追加/覆盖/忽略信息，让冗余与冲突悬而不决；(ii) *Aimless Retrieval*——当初始查询不完整、或与存储记忆语义错配时，一次性检索或浅层改写无法浮出所需证据；没有战略指导，后续查询也**收窄不了信息差**。

**EN.** **Setup.** To empirically validate this diagnosis, we conduct a preliminary study on a subset of LoCoMo (Maharana et al., 2024), focusing on reasoning-intensive queries by excluding adversarial samples. We compare three progressively stronger baselines using GPT-4o-mini (Hurst et al., 2024) as the backbone: (i) *Static*, which performs memory construction followed by one-shot top-30 retrieval; (ii) *Unguided Active*, which adds iterative query rewriting without strategic guidance; and (iii) *Strategic Active*, which introduces a planner to guide both construction and retrieval.

**中.** **设定。** 为从实证上验证这一诊断，我们在 LoCoMo（Maharana et al., 2024）的一个子集上做预实验，通过排除对抗样本聚焦**推理密集**的查询。以 GPT-4o-mini（Hurst et al., 2024）为后端，对比三档逐步增强的基线：(i) *Static*——先做记忆构建，再做一次性 top-30 检索；(ii) *Unguided Active*——加入迭代查询改写，但**无战略指导**；(iii) *Strategic Active*——引入 planner 同时指导构建与检索。

**EN.** We report token-level F1, BLEU-1 (B1), and LLM-as-a-judge accuracy (ACC). More evaluation details are provided in Appendix B.1. **Empirical analysis.** Table 1 reveals two findings: (i) *Retrieval provides capability*: Unguided Active (54.6% Acc) outperforms Static (52.6%), confirming that one-shot retrieval often fails to surface the required evidence when the initial query is incomplete or mismatched with memory, which directly reflects *Aimless Retrieval*. (ii) *Reasoning provides control*: Strategic Active achieves a larger leap to 59.2% Acc. Since it shares the same active operators as Unguided Active, this gap reflects the value of explicit strategic guidance in addressing both *Aimless Retrieval* and *Myopic Construction*. Case studies in Appendix B.2 further illustrate both pathologies with concrete examples of redundant entries and retrieval drift. These findings suggest that active memory operations alone are insufficient: explicit strategic reasoning is needed to guide both construction and retrieval.

**中.** 我们报告 token 级 F1、BLEU-1（B1）与 LLM-as-a-judge 准确率（ACC）。更多评测细节见附录 B.1。**实证分析。** 表 1 给出两个发现：(i) *检索提供能力*——Unguided Active（54.6% Acc）优于 Static（52.6%），印证了初始查询不完整或与记忆错配时，一次性检索常常浮不出所需证据，这**直接对应** *Aimless Retrieval*；(ii) *推理提供控制*——Strategic Active 跃升更大，到 59.2% Acc。由于它与 Unguided Active **共享同一套主动算子**，这一差距反映的是**显式战略指导**在同时化解 *Aimless Retrieval* 与 *Myopic Construction* 上的价值。附录 B.2 的案例研究用冗余条目与检索漂移的具体例子进一步展示了这两种病症。这些发现说明：**仅有主动记忆操作是不够的——构建与检索都需要显式的战略推理来引导。**

## 4. Methodology / 方法

**EN.** Motivated by the memory cycle effect (Sec. 3.2) and strategic blindness (Sec. 3.3), we present MemMA, a plug-and-play multi-agent framework that coordinates the memory cycle along its forward and backward paths (Fig. 2). Sec. 4.1 describes the forward path: a planner-worker architecture that separates strategic reasoning from low-level execution to address strategic blindness. Sec. 4.2 describes the backward path: an in-situ self-evolution mechanism that addresses sparse, delayed feedback by generating synthetic probe QA immediately after each session, providing dense, localized supervision for memory repair before the current memory is committed.

**中.** 受记忆周期效应（§3.2）与战略盲区（§3.3）启发，我们提出 **MemMA**：一个即插即用的多智能体框架，沿前向与后向两条路径协同记忆周期（图 2）。§4.1 描述**前向路径**：一个 planner-worker 架构，把战略推理与低层执行分离以应对战略盲区。§4.2 描述**后向路径**：一个就地自演化机制，通过在**每个 session 之后立即**生成合成探针 QA、在当前记忆被提交之前提供**密集而局部**的监督信号，来应对稀疏延迟反馈。

### 4.1 Reasoning-Aware Coordination over the Forward Path / 前向路径上的推理感知协调

**EN.** MemMA coordinates online construction, iterative retrieval, and answer-time utilization through specialized yet tightly coupled agents. Its key design principle is to separate strategic reasoning (what to store, what is missing, and when to stop) from low-level execution (memory editing, evidence retrieval, and answer generation).

**中.** MemMA 通过**专职但紧耦合**的 agent 来协调在线构建、迭代检索与作答期利用。其核心设计原则是把**战略推理**（存什么、缺什么、何时停止）与**低层执行**（记忆编辑、证据检索、答案生成）**分离**。

**EN.** **Pipeline Overview.** MemMA uses a planner-worker architecture with four roles: (i) a *Meta-Thinker* π_p for high-level strategic reasoning; (ii) a *Memory Manager* π_s for memory editing; (iii) a *Query Reasoner* π_r for iterative query refinement; and (iv) an *Answer Agent* π_a for final response generation. During *construction*, when a new dialogue chunk c_t arrives, π_p analyzes it against existing memory M̄_{t-1} and produces meta-guidance on what to retain, consolidate, or resolve. Conditioned on the guidance, π_s selects an atomic edit to update M_{t-1} to M_t. During *question answering*, given a query q, π_r retrieves candidate evidence from M_T and iteratively refines its search. At each step, π_p judges whether the current evidence is sufficient; if not, it identifies the most critical gap and directs π_r to refine the query toward complementary evidence. The loop ends when π_p deems the evidence sufficient or a budget H is reached. Then π_a generates the final answer. We detail each component below.

**中.** **流水线概览。** MemMA 采用含四个角色的 planner-worker 架构：(i) *Meta-Thinker* π_p，负责高层战略推理；(ii) *Memory Manager* π_s，负责记忆编辑；(iii) *Query Reasoner* π_r，负责迭代式查询细化；(iv) *Answer Agent* π_a，负责最终回答生成。在*构建*期，新对话块 c_t 到达时，π_p 对照既有记忆 M̄_{t-1} 分析它，并产出"该保留、整合、还是解决什么"的元指导。条件于该指导，π_s 选择一个**原子编辑**把 M_{t-1} 更新为 M_t。在*问答*期，给定查询 q，π_r 从 M_T 检索候选证据并迭代细化搜索。每一步 π_p 判断当前证据是否充分；若不充分，它识别**最关键的缺口**并指导 π_r 把查询细化向**互补证据**。当 π_p 认为证据充分、或达到预算 H 时循环结束。随后 π_a 生成最终答案。下文逐一说明各组件。

**EN.** **Meta-Thinker** π_p. π_p is the planning layer of MemMA, responsible for both construction and retrieval guidance. It produces phase-specific guidance conditioned on the current input and a bounded memory view [Eq. 1], where g_t^S is construction guidance at step t and g_{q,h}^R is retrieval guidance at refinement step h. Here E_h denotes the evidence accumulated up to step h, U_h={u_0,…,u_h} denotes the query history, and M̄ denotes a bounded view of the memory bank, e.g., top-k recent or semantically related entries. *Construction*: g_t^S provides a set of focus points that flag information importance, redundancy with existing entries, and potential conflicts. These focus points steer π_s toward globally consistent memories rather than indiscriminate accumulation. *Retrieval*: g_{q,h}^R is a critique of the current evidence E_h. π_p evaluates coverage, consistency, and specificity with respect to q. If the evidence is sufficient, it returns ANSWERABLE; otherwise, it returns NOT-ANSWERABLE together with a diagnosis of what is missing and how to retrieve it, e.g., a missing attribute or temporal scope. This encourages orthogonal evidence acquisition rather than near-duplicate searches.

**中.** **Meta-Thinker** π_p。π_p 是 MemMA 的**规划层**，同时负责构建与检索两方面的指导。它条件于当前输入与**有界记忆视图**产出**相位相关**的指导 [式 1]，其中 g_t^S 是第 t 步的构建指导，g_{q,h}^R 是细化第 h 步的检索指导。此处 E_h 表示到第 h 步累积的证据，U_h={u_0,…,u_h} 表示查询历史，M̄ 表示记忆库的**有界视图**，例如 top-k 最近或语义相关的条目。*构建*：g_t^S 提供一组 **focus point**，标记信息重要性、与既有条目的冗余、以及潜在冲突。这些 focus point 把 π_s 引向**全局一致**的记忆，而不是无差别的堆积。*检索*：g_{q,h}^R 是对当前证据 E_h 的**批判（critique）**。π_p 就 q 评估其**覆盖度、一致性、特异性**。若证据充分，返回 ANSWERABLE；否则返回 NOT-ANSWERABLE，并附上"缺什么、如何取回"的诊断，例如缺失某个属性或时间范围。这鼓励**正交的证据获取**，而非近似重复的搜索。

**EN.** **Memory Manager** π_s. π_s performs atomic memory edits based on the current chunk, bounded context, and guidance from π_p. Given c_t, M̄_{t-1}, and g_t^S, it selects an action a_t^S∈{ADD, UPDATE, DELETE, NONE} [Eq. 2]. The guidance signal g_t^S helps π_s filter noise, consolidate redundancy, and resolve conflicts at the source rather than blindly appending. π_s is backend-agnostic and can wrap diverse memory implementations such as LightMem (Fang et al., 2025) and A-Mem (Xu et al., 2025).

**中.** **Memory Manager** π_s。π_s 依据当前块、有界上下文与来自 π_p 的指导执行**原子记忆编辑**。给定 c_t、M̄_{t-1} 与 g_t^S，它选择一个动作 a_t^S∈{ADD, UPDATE, DELETE, NONE} [式 2]。指导信号 g_t^S 帮助 π_s 去噪、整合冗余、**在源头**解决冲突，而不是盲目追加。π_s 与存储后端**解耦**，可以包住多种记忆实现，如 LightMem（Fang et al., 2025）与 A-Mem（Xu et al., 2025）。

**EN.** **Query Reasoner** π_r. π_r implements the *active retrieval policy*. To overcome the *Aimless Retrieval* (Sec. 3.3), it replaces one-shot search with an iterative *Refine-and-Probe* loop. Let u_0=q be the initial query and U_h={u_0,…,u_h} the query history. At step h, when π_p deems the current evidence E_h NOT-ANSWERABLE, it emits guidance g_{q,h}^R. π_r then proposes the next query and retrieves additional evidence [Eq. 3]. The loop terminates when π_p returns ANSWERABLE or the budget H is reached. Each refinement step targets the specific information gap diagnosed by π_p, so successive queries narrow the deficit rather than drifting across redundant rewrites. Full query rewrite prompt templates are in Appendix D.

**中.** **Query Reasoner** π_r。π_r 实现*主动检索策略*。为克服 *Aimless Retrieval*（§3.3），它用迭代的 *Refine-and-Probe*（细化—探测）循环取代一次性搜索。设 u_0=q 为初始查询、U_h={u_0,…,u_h} 为查询历史。在第 h 步，当 π_p 判定当前证据 E_h 为 NOT-ANSWERABLE 时，它发出指导 g_{q,h}^R。π_r 随即提出下一条查询并检索额外证据 [式 3]。当 π_p 返回 ANSWERABLE 或达到预算 H 时循环终止。每一次细化都**瞄准 π_p 诊断出的具体信息缺口**，因此后续查询是在**收窄差距**，而不是在冗余改写之间漂移。完整的查询改写 prompt 模板见附录 D。

**EN.** **Answer Agent** π_a. Once the retrieval loop terminates, π_a generates the final answer ŷ(q) based on the query and the final evidence set E(q)=E_H [Eq. 4], where F_{π_a} denotes a generation function (e.g., an LLM call). In our experiments, π_a is kept frozen to decouple answer-generation capacity from memory quality, so that gains can be attributed to coordination over the memory cycle rather than to the parametric knowledge of π_a.

**中.** **Answer Agent** π_a。检索循环一终止，π_a 便依据查询与最终证据集 E(q)=E_H 生成最终答案 ŷ(q) [式 4]，其中 F_{π_a} 表示一个生成函数（如一次 LLM 调用）。在我们的实验中，π_a **保持冻结**，以把"答案生成能力"与"记忆质量"解耦，从而让增益可以归因于**记忆周期上的协调**，而不是 π_a 的参数化知识。

### 4.2 In-Situ Self-Evolving Memory Construction / 就地自演化记忆构建

**EN.** A major bottleneck in the memory cycle is that feedback for construction is typically sparse and delayed. The utility of a storage decision made in session τ may become observable only much later, when the agent fails a downstream question. Optimizing construction solely from final-task outcomes makes credit assignment difficult and lets early omissions propagate uncorrected. To address this, we introduce *in-situ self-evolving memory construction*, which provides dense intermediate feedback for the construction stage. Instead of waiting for a future user query to expose a memory failure, MemMA synthesizes a set of probe QA pairs after each session and uses them to verify and repair the current memory before it is committed.

**中.** 记忆周期中的一个主要瓶颈是：**构建的反馈通常稀疏且延迟**。在会话 τ 做出的某个存储决策的效用，可能要到**很久之后** agent 在某个下游问题上失败时才变得可观测。仅从终局任务结果去优化构建，会让**信用分配**变难，并让早期的遗漏**一路传播不被修正**。为应对这一点，我们引入*就地自演化记忆构建*，为构建阶段提供**密集的中间反馈**。MemMA 不去等待未来的某个用户查询来暴露记忆失败，而是在**每个会话之后**合成一组探针 QA 对，用它们在当前记忆**被提交之前**进行验证与修复。

**EN.** **Probe Generation.** Let s_τ denote the current session, and M_s^(0) denote the provisional memory state obtained after applying the construction policy of Sec. 4.1 to s_τ. To obtain intermediate supervision, we construct a probe set [Eq. 5], where each (q_j,y_j) is a synthetic question–answer pair grounded in s_τ and its relevant historical context M̄_{τ-1}. The questions are designed to test whether the provisional memory faithfully captures and can retrieve information introduced in the current session, covering single-session factual recall, cross-session relational reasoning, and temporal inference (Shen et al., 2026). This turns a delayed end-task signal into J localized supervision signals immediately after construction. Design details are in Appendix E.1.

**中.** **探针生成。** 设 s_τ 表示当前会话，M_s^(0) 表示对 s_τ 施加 §4.1 的构建策略后得到的**暂存记忆状态**。为获得中间监督，我们构造一个探针集合 [式 5]，其中每个 (q_j,y_j) 都是**扎根于** s_τ 及其相关历史上下文 M̄_{τ-1} 的合成问答对。这些问题旨在测试：暂存记忆是否忠实捕获了、且能否检索到当前会话引入的信息——覆盖**单会话事实召回、跨会话关系推理、时间推理**（Shen et al., 2026）。这把一个延迟的终局信号，转成构建后**立即产生的 J 个局部监督信号**。设计细节见附录 E.1。

**EN.** **In-Situ Verification.** Given Q_τ, MemMA verifies the provisional memory state M_s^(0) immediately after the initial construction pass. For each probe q_j, we retrieve top-k evidence from M_s^(0) and generate an answer with π_a [Eq. 6]. A probe is considered failed if ŷ_j is judged incorrect with respect to y_j. Such failures provide localized evidence that M_s^(0) is insufficient for information introduced in or linked to s_τ.

**中.** **就地验证。** 给定 Q_τ，MemMA 在初次构建通过后**立即**验证暂存记忆状态 M_s^(0)。对每个探针 q_j，我们从 M_s^(0) 检索 top-k 证据并用 π_a 生成答案 [式 6]。若 ŷ_j 相对 y_j 被判定为错，该探针即视为**失败**。这类失败提供了**局部证据**，表明 M_s^(0) 对 s_τ 中引入或与之关联的信息**支撑不足**。

**EN.** **Evidence-grounded Repair.** For each failed probe, a reflection module converts the failure into a repair proposal. Conditioned on the question, gold answer, predicted answer, retrieved evidence, and the provisional memory state (q_j,y_j,ŷ_j,E_j,M_s^(0)), the reflection module identifies whether the failure reflects missing information or memory content that is difficult to retrieve in its current form, and then proposes a candidate repair fact. Collecting all failed probes in the current batch yields a set of repair proposals [Eq. 7], where Q_τ^fail⊆Q_τ denotes the failed probes.

**中.** **证据锚定的修复。** 对每个失败探针，一个反思模块把失败转成一条修复提案。条件于问题、gold 答案、预测答案、检索到的证据以及暂存记忆状态 (q_j,y_j,ŷ_j,E_j,M_s^(0))，反思模块判断该失败反映的是**信息缺失**，还是**记忆内容以其当前形态难以被检索**，然后提出一条候选修复事实。把当前批次内所有失败探针收集起来，得到修复提案集合 [式 7]，其中 Q_τ^fail⊆Q_τ 表示失败探针。

**EN.** **Semantic Consolidation.** Applying all repairs in R_τ directly would reintroduce redundancy or conflicts, e.g., when two probes request overlapping or inconsistent additions. Therefore we consolidate the candidate repair facts against M_s^(0). For each candidate fact, the consolidation step assigns one of three actions with respect to the existing memory: SKIP if it is redundant, MERGE if it complements an existing entry, or INSERT if it is novel. This resolves both conflicts with the existing memory and conflicts across repair proposals before any update is written back. The refined memory is obtained as [Eq. 8], where REFINE denotes consolidation followed by write-back over R_τ. In this way, utilization failures are detected and repaired during construction before they propagate into later memory updates, while keeping the evolving memory compact and internally consistent.

**中.** **语义整合。** 直接施加 R_τ 中的全部修复会**重新引入冗余或冲突**，例如当两个探针请求**重叠或不一致**的新增时。因此我们把候选修复事实对照 M_s^(0) 做整合。对每条候选事实，整合步骤相对既有记忆赋予三种动作之一：`SKIP`（若冗余）、`MERGE`（若补全某条既有条目）、`INSERT`（若为新信息）。这在**任何更新被写回之前**，同时消解"与既有记忆的冲突"和"修复提案之间的冲突"。精炼后的记忆由 [式 8] 得到，其中 REFINE 表示对 R_τ 做整合再写回。如此，利用阶段的失败会在**构建期**就被检出并修复，避免其传播进后续记忆更新，同时让演化中的记忆保持**紧凑且内部一致**。

## 5. Experiments / 实验

### 5.1 Experimental Setup / 实验设置

**EN.** **Datasets.** We primarily evaluate MemMA on LoCoMo (Maharana et al., 2024), a benchmark for long-horizon conversational memory. Following prior work (Yan et al., 2025; Fang et al., 2025), we exclude the adversarial subset and focus on the reasoning-intensive QA setting. All LoCoMo experiments use a fixed conversation subset (152 QA pairs). To further evaluate generalization beyond the conversational setting, we additionally consider LongMemEval-S (Jimenez et al., 2024), a larger-scale long-horizon memory benchmark, and SWE-bench-Verified-mini (Jimenez et al., 2024), a realistic agentic coding benchmark. More dataset details are provided in Appendix F.1.

**中.** **数据集。** 我们主要在 **LoCoMo**（Maharana et al., 2024）上评测 MemMA——一个面向长时程对话记忆的基准。遵循先前工作（Yan et al., 2025; Fang et al., 2025），我们**排除对抗子集**、聚焦推理密集的 QA 设定。所有 LoCoMo 实验使用一个**固定**的对话子集（152 个 QA 对）。为进一步评估在对话场景之外的泛化，我们额外考虑 **LongMemEval-S**（Jimenez et al., 2024）——一个更大规模的长时程记忆基准——以及 **SWE-bench-Verified-mini**（Jimenez et al., 2024），一个真实的 agentic 编程基准。更多数据集细节见附录 F.1。

**EN.** **Baselines.** We compare against two passive baselines: *Full Text* and *Naive RAG* (Gao et al., 2023), and four active memory systems: *LangMem* (LangChain, 2025), *Mem0* (Chhikara et al., 2025), *A-Mem* (Xu et al., 2025), and *LightMem* (Fang et al., 2025). Additional baseline details are in Appendix F.2.

**中.** **基线。** 我们对比两个**被动**基线：*Full Text* 与 *Naive RAG*（Gao et al., 2023）；以及四个**主动**记忆系统：*LangMem*（LangChain, 2025）、*Mem0*（Chhikara et al., 2025）、*A-Mem*（Xu et al., 2025）与 *LightMem*（Fang et al., 2025）。更详细的基线说明见附录 F.2。

**EN.** **Evaluation Protocol.** Following prior work (Yan et al., 2025; Chhikara et al., 2025), we report three metrics: token-level F1 (F1), BLEU-1 (B1), and LLM-as-a-judge accuracy (ACC). F1 and B1 measure lexical overlap with the reference answer; ACC measures semantic correctness via a judge model. GPT-4o-mini (Hurst et al., 2024) and Claude-Haiku-4.5 (Anthropic, 2025) are used as the backbones for the Memory Manager, Meta-Thinker, and Query Reasoner. To isolate memory construction quality from answer-generation capacity, we fix GPT-4o-mini as both the Answer Agent and the LLM judge across all experiments. The retrieval budget is top-30 entries, the iterative refinement budget is H=3, and we generate J=5 probe QA pairs per session for self-evolution. Additional implementation details are in Appendix F.3.

**中.** **评测协议。** 遵循先前工作（Yan et al., 2025; Chhikara et al., 2025），我们报告三个指标：token 级 F1（F1）、BLEU-1（B1）以及 LLM-as-a-judge 准确率（ACC）。F1 与 B1 衡量与参考答案的**词面重叠**；ACC 通过 judge 模型衡量**语义正确性**。GPT-4o-mini（Hurst et al., 2024）与 Claude-Haiku-4.5（Anthropic, 2025）用作 Memory Manager、Meta-Thinker 与 Query Reasoner 的后端。为把**记忆构建质量**与**答案生成能力**隔离，我们在所有实验中把 GPT-4o-mini **同时固定为** Answer Agent 与 LLM judge。检索预算为 top-30 条目，迭代细化预算为 H=3，自演化时每会话生成 J=5 个探针 QA 对。更多实现细节见附录 F.3。

### 5.2 Main Comparison with Baselines / 与基线的主对比

**EN.** To evaluate MemMA, we compare it with baselines. We use LightMem as the storage backend of MemMA, denoted MemMA_LM. GPT-4o-mini and Claude-Haiku-4.5 are the backbones. Other settings follow Sec. 5.1. Table 2 reports the results. Three findings emerge: (i) MemMA_LM achieves the *best overall performance* under both backbones. Under GPT-4o-mini, it reaches 49.40 F1, 38.28 B1, and 81.58 ACC, improving over LightMem by +4.82 F1, +1.62 B1, and +5.92 ACC. Under Claude-Haiku-4.5, it again achieves the best overall ACC, improving from 73.03 to 76.97 over LightMem. (ii) *The gains are strong at the category level.* Under GPT-4o-mini, MemMA_LM improves most on Multi-Hop and Single-Hop, raising ACC from 65.62 to 78.12 and from 78.57 to 82.86, respectively. The Multi-Hop gains are consistent with diagnosis-guided iterative retrieval helping recover distributed evidence, while the Single-Hop gains suggest that construction guidance and self-evolution help preserve precise answer-bearing details. (iii) MemMA_LM improves an already strong baseline. LightMem is already the strongest baseline, yet MemMA_LM further improves it under both backbones, suggesting that the gain comes from memory-cycle coordination rather than a stronger storage backend.

**中.** 为评估 MemMA，我们与基线对比。我们用 LightMem 作为 MemMA 的存储后端，记为 MemMA_LM。后端为 GPT-4o-mini 与 Claude-Haiku-4.5，其余设置遵循 §5.1。表 2 报告结果，浮现三个发现：(i) MemMA_LM 在两种后端下都取得*最佳整体表现*。GPT-4o-mini 下达到 49.40 F1、38.28 B1、81.58 ACC，相对 LightMem 提升 +4.82 F1、+1.62 B1、+5.92 ACC。Claude-Haiku-4.5 下同样取得最佳整体 ACC，从 73.03 提升到 76.97。(ii) *在类别层面增益显著。* GPT-4o-mini 下 MemMA_LM 在 **Multi-Hop 与 Single-Hop** 上提升最大，ACC 分别从 65.62 升到 78.12、从 78.57 升到 82.86。多跳增益与"诊断引导的迭代检索帮助找回分散证据"一致；单跳增益则表明**构建指导与自演化有助于保住精确的、承载答案的细节**。(iii) MemMA_LM 提升的是一个**本已很强**的基线。LightMem 已是最强基线，而 MemMA_LM 在两种后端下都进一步提升它，表明增益来自**记忆周期的协调**，而非更强的存储后端。

### 5.3 Flexibility across Storage Backends / 跨存储后端的灵活性

**EN.** To assess the flexibility of MemMA across storage backends, we instantiate it on top of three memory systems: Single-Agent (Yan et al., 2025) (MemMA_SA), A-Mem (MemMA_AM), and LightMem (MemMA_LM). All other components and settings are fixed as in Sec. 5.1. Table 3 reports results on LoCoMo under GPT-4o-mini. Two observations emerge. (i) MemMA consistently improves all backends. In terms of ACC, MemMA improves the Single-Agent backend from 52.60 to 84.87, A-Mem from 52.63 to 78.29, and LightMem from 75.66 to 81.58. For A-Mem and LightMem, the gains are also consistent in F1 and B1. For the weaker Single-Agent backend, B1 decreases even though ACC rises sharply, suggesting that MemMA improves semantic correctness more than lexical overlap in this setting. These results indicate that MemMA improves long-horizon memory across diverse storage implementations. (ii) *The gains of MemMA complement storage quality rather than replace it.* Among the enhanced variants, MemMA_LM achieves the strongest overall performance, which is consistent with LightMem being the strongest standalone backend. This pattern suggests that MemMA improves how memory is coordinated, rather than relying on a particular storage design.

**中.** 为评估 MemMA 跨存储后端的灵活性，我们把它实例化在三种记忆系统之上：Single-Agent（Yan et al., 2025）（MemMA_SA）、A-Mem（MemMA_AM）与 LightMem（MemMA_LM）。其余组件与设置全部固定如 §5.1。表 3 报告 GPT-4o-mini 下 LoCoMo 的结果，浮现两点观察。(i) **MemMA 一致地改善所有后端。** 以 ACC 计，MemMA 把 Single-Agent 后端从 52.60 提到 84.87、A-Mem 从 52.63 提到 78.29、LightMem 从 75.66 提到 81.58。对 A-Mem 与 LightMem，F1 与 B1 的提升也一致。对更弱的 Single-Agent 后端，**ACC 大幅上升的同时 B1 反而下降**，表明在该设定下 MemMA 改善的是**语义正确性**多于词面重叠。这些结果表明 MemMA 能跨多样存储实现改善长时程记忆。(ii) *MemMA 的增益是**补足**存储质量，而非**取代**它。* 在各增强变体中，MemMA_LM 取得最强整体表现，与"LightMem 本身是最强单机后端"一致。这一模式表明 MemMA 改善的是**记忆如何被协调**，而不是依赖某种特定的存储设计。

### 5.4 In-depth Dissection of MemMA / MemMA 的深入剖析

**EN.** **Ablation Studies.** To understand the contributions of key components in MemMA, we implement three ablated variants on the Single-Agent backend: (i) MemMA/C removes the Meta-Thinker guidance during construction and directly uses the Memory Manager for memory writing; (ii) MemMA/R removes iterative retrieval, reverting to one-shot retrieval based on semantic similarity; and (iii) MemMA/E removes the probe-and-repair loop of in-situ self-evolving memory construction and directly commits M_s^(0) to the memory bank. Fig. 3 reports the results under GPT-4o-mini and Claude-Haiku-4.5. The full MemMA_SA achieves the strongest overall performance, while the variants reveal complementary weaknesses. Specifically: (i) *Iterative retrieval is the most critical forward-path component.* MemMA_SA/R causes the largest drop under both backbones, reducing ACC from 84.87 to 70.39 with GPT-4o-mini and from 88.82 to 81.58 with Claude-Haiku-4.5. This confirms that one-shot retrieval remains a major bottleneck and that diagnosis-guided refinement is essential for narrowing the information gap. (ii) *Self-evolution repairs construction omissions.* MemMA_SA/E causes the second-largest degradation (ACC: 84.87 → 73.68 with GPT-4o-mini). The large ACC drop with only moderate F1 change suggests that self-evolution mainly improves semantic correctness by repairing missing information during construction. (iii) *Construction guidance reduces upstream noise.* MemMA_SA/C reduces ACC from 88.82 to 83.55 with Claude-Haiku-4.5. This shows that construction decisions benefit from explicit strategic guidance rather than local heuristics alone, as the Meta-Thinker helps determine what should be retained, consolidated, or resolved before information enters the memory bank. These ablations confirm that MemMA's gains come from complementary improvements on both paths of the memory cycle.

**中.** **消融研究。** 为理解 MemMA 中各关键组件的贡献，我们在 Single-Agent 后端上实现三个消融变体：(i) **MemMA/C** 去掉构建期的 Meta-Thinker 指导，直接用 Memory Manager 写记忆；(ii) **MemMA/R** 去掉迭代检索，退回基于语义相似度的一次性检索；(iii) **MemMA/E** 去掉就地自演化记忆构建中的"探针—修复"环，直接把 M_s^(0) 提交进记忆库。图 3 报告 GPT-4o-mini 与 Claude-Haiku-4.5 下的结果。完整的 MemMA_SA 取得最强整体表现，各变体则**暴露互补的弱点**。具体地：(i) *迭代检索是最关键的前向路径组件。* MemMA_SA/R 在两种后端下都造成**最大跌幅**：GPT-4o-mini 下 ACC 从 84.87 降到 70.39，Claude-Haiku-4.5 下从 88.82 降到 81.58。这证实一次性检索仍是主要瓶颈，诊断引导的细化对收窄信息差**不可或缺**。(ii) *自演化修复构建遗漏。* MemMA_SA/E 造成第二大退化（GPT-4o-mini 下 ACC：84.87 → 73.68）。**ACC 大跌而 F1 只是中等变化**，表明自演化主要通过**修复构建期缺失的信息**来改善语义正确性。(iii) *构建指导减少上游噪声。* Claude-Haiku-4.5 下 MemMA_SA/C 把 ACC 从 88.82 降到 83.55。这说明构建决策能从**显式战略指导**中获益，而非仅靠局部启发式——Meta-Thinker 帮助在信息进入记忆库之前判定该保留、整合、还是解决什么。这些消融证实 MemMA 的增益来自记忆周期**两条路径上的互补改进**。

**EN.** **Process-level Diagnostics.** We directly examine whether MemMA mitigates the two failure modes identified in Sec. 3.3. For *Myopic Construction*, we introduce construction-process diagnostics derived from self-refinement traces. GPT-4o-mini is used as the backbone model and LightMem is used as the storage backend; all other settings follow Sec. 5.1. We measure *construction gap closure*, the fraction of probe-detected construction gaps repaired before memory commitment. MemMA closes 59/64 detected construction gaps, achieving 92.2% gap closure. This provides direct process-level evidence that the backward path repairs construction omissions before they enter persistent memory.

**中.** **过程级诊断。** 我们直接检验 MemMA 是否缓解了 §3.3 中识别的两种失败模式。对 *Myopic Construction*，我们引入从自精炼轨迹导出的构建过程诊断。后端模型用 GPT-4o-mini、存储后端用 LightMem，其余设置遵循 §5.1。我们度量 *construction gap closure*（构建缺口闭合率）——**在记忆提交之前被修复的、探针检出的构建缺口的比例**。MemMA 闭合了 **59/64** 个检出的构建缺口，达到 **92.2% 的缺口闭合率**。这提供了直接的**过程级证据**：后向路径在构建遗漏进入持久记忆**之前**就修复了它们。

**EN.** For *Aimless Retrieval*, we measure whether retrieval surfaces answer-bearing evidence before generation using two metrics: *evidence coverage*, the average fraction of normalized gold-answer tokens covered by retrieved memories, and *Hit@≥80%*, the fraction of questions whose retrieved memories cover at least 80% of the gold-answer tokens. For MemMA, we report both the initial top-k evidence E_0 and the final accumulated evidence E_H after iterative retrieval. Results are shown in Tab. 4. MemMA_LM outperforms all baselines on both metrics, while the improvement from E_0 to E_H indicates that diagnosis-guided iterative retrieval surfaces additional answer-bearing evidence, providing direct process-level support for mitigating *Aimless Retrieval*.

**中.** 对 *Aimless Retrieval*，我们用两个指标度量**生成之前**检索是否浮出了承载答案的证据：*evidence coverage*（归一化后 gold 答案 token 被检索记忆覆盖的平均比例）与 *Hit@≥80%*（检索记忆覆盖至少 80% gold 答案 token 的问题占比）。对 MemMA，我们同时报告初始 top-k 证据 E_0 与迭代检索后最终累积的证据 E_H。结果见表 4。MemMA_LM 在两个指标上都优于所有基线；而 E_0→ E_H 的提升表明**诊断引导的迭代检索确实多浮出了一批承载答案的证据**，为缓解 *Aimless Retrieval* 提供了直接的过程级支持。

**EN.** **Impact of retrieval budget k.** We vary k∈{10,20,30,40,50} on both Single-Agent and LightMem backends and report results in Fig. 4. We observe that the optimal k depends on storage quality. For MemMA_LM, ACC peaks at k=30–40 (81.58) and declines at k=50 (79.61), indicating a sweet spot beyond which additional retrieval introduces noise. For MemMA_SA, ACC increases steadily from 75.66 at k=10 to 84.21 at k=50, without saturation. We attribute this contrast to storage quality: stronger backends produce higher-quality, less redundant entries, so a moderate k suffices and excess retrieval dilutes the evidence; weaker backends need a larger k to retrieve enough evidence from sparser memory banks.

**中.** **检索预算 k 的影响。** 我们在 Single-Agent 与 LightMem 两种后端上变化 k∈{10,20,30,40,50}，结果见图 4。我们观察到**最优 k 取决于存储质量**。对 MemMA_LM，ACC 在 k=30–40 达峰（81.58），在 k=50 回落（79.61），说明存在一个**甜点区**，超过之后额外检索反而引入噪声。对 MemMA_SA，ACC 从 k=10 的 75.66 稳步升到 k=50 的 84.21，**不饱和**。我们把这一对比归因于**存储质量**：更强的后端产出更高质量、更少冗余的条目，因此中等 k 就够，过量检索反而稀释证据；更弱的后端则需要更大的 k，才能从更稀疏的记忆库里捞到足够证据。

**EN.** **Impact of retrieval refinement budget H.** We vary the refinement budget H∈{0,1,2,3,4,5} under GPT-4o-mini and Claude-Haiku-4.5. The results of MemMA_SA and MemMA_LM are reported in Fig. 5. We observe that ACC improves sharply from one-shot retrieval (H=0) to a small H, and then declines. For example, MemMA_SA's ACC rises from 78.95 at H=0 to 85.53 at H=2, then drops back to 81.58 at H=4. This shows that diagnosis-guided refinement converges quickly: one or two additional retrieval rounds suffice to close most information gaps, while further iterations risk retrieval drift. This validates the effectiveness of the Meta-Thinker's answerability diagnosis, which directs each refinement step toward the specific missing evidence rather than redundant searches. More analysis of the impact of probe generation model is in Appendix G.

**中.** **检索细化预算 H 的影响。** 我们在 GPT-4o-mini 与 Claude-Haiku-4.5 下变化细化预算 H∈{0,1,2,3,4,5}，MemMA_SA 与 MemMA_LM 的结果见图 5。我们观察到 ACC 从一次性检索（H=0）到较小的 H **陡升**，随后**回落**。例如 MemMA_SA 的 ACC 从 H=0 的 78.95 升到 H=2 的 85.53，再降到 H=4 的 81.58。这说明**诊断引导的细化收敛很快**：**一两轮**额外检索就足以闭合大部分信息缺口，更多迭代则有**检索漂移**的风险。这验证了 Meta-Thinker **可答性诊断**的有效性——它把每一步细化导向**具体的缺失证据**，而非冗余搜索。探针生成模型影响的更多分析见附录 G。

### 5.5 Case Studies / 案例研究

**EN.** We conduct a case study to better understand why MemMA improves long-horizon QA. Our findings indicate that: (i) on the forward path, construction-time Meta-Thinker guidance determines whether answer-bearing details survive in memory, while diagnosis-guided iterative retrieval determines whether missing evidence is surfaced before the system commits to an answer. Importantly, iterative retrieval cannot compensate for details that were never preserved during construction. The cases also show that the retrieval controller and the storage backend play distinct roles: the Meta-Thinker and Query Reasoner identify the information gap, while the backend determines whether the required evidence can actually be recovered; (ii) on the backward path, in-situ self-evolution converts local probe failures into targeted memory repairs that transfer to downstream QA, for example by inserting missing named entities, sharpening vague entity descriptions, and completing partial evidence clusters. Detailed examples are in Appendix H.

**中.** 我们做案例研究，以更好理解 MemMA 为何能改善长时程问答。我们的发现表明：(i) 在前向路径上，**构建期的 Meta-Thinker 指导决定承载答案的细节能否在记忆中存活**，而**诊断引导的迭代检索决定在系统给出答案之前，缺失的证据能否被浮出**。要紧的是：**迭代检索无法补偿在构建期从未被保留下来的细节**。案例还表明**检索控制器与存储后端扮演不同角色**：Meta-Thinker 与 Query Reasoner 负责**识别**信息缺口，后端则决定所需证据**能否真的被取回**；(ii) 在后向路径上，就地自演化把局部探针失败转成**可迁移到下游 QA** 的定向记忆修复，例如插入缺失的命名实体、锐化含糊的实体描述、补全不完整的证据簇。详细例子见附录 H。

## 6. Conclusion / 结论

**EN.** We introduce MemMA, a plug-and-play multi-agent framework that coordinates the memory cycle along its forward and backward paths. On the forward path, a Meta-Thinker separates strategic reasoning from low-level execution, addressing strategic blindness in construction and retrieval. On the backward path, in-situ self-evolution converts probe QA failures into direct memory repair before the memory is committed. Experiments on LoCoMo show that MemMA outperforms all baselines across multiple backbones and consistently improves three different storage backends.

**中.** 我们提出 **MemMA**：一个即插即用的多智能体框架，沿前向与后向两条路径协同记忆周期。在前向路径上，Meta-Thinker 把战略推理与低层执行分离，应对构建与检索中的**战略盲区**。在后向路径上，就地自演化把探针 QA 的失败转成**记忆提交之前的直接修复**。LoCoMo 上的实验表明，MemMA 跨多种后端优于全部基线，并一致地改善三种不同的存储后端。

## 7. Limitations / 局限性（全文）

**EN.** Our evaluation focuses on a dialogue-centric long-horizon memory benchmark. While LoCoMo covers diverse question types, including single-hop, multi-hop, temporal, and open-domain reasoning, it does not capture all settings in which persistent memory may be needed. In addition, the backward path assumes that interaction streams can be organized into sessions and that synthetic probe QA can provide useful localized supervision. These assumptions are natural for the benchmark studied here, but may require adaptation in settings with less clear session boundaries or more open-ended interaction structure.

**中.** 我们的评估聚焦于一个**对话中心**的长时程记忆基准。LoCoMo 虽覆盖多样的题型——单跳、多跳、时间、开放域推理——但它**并不能涵盖所有可能需要持久记忆的场景**。此外，后向路径**假定交互流可以被组织成会话**，且**合成探针 QA 能提供有用的局部监督**。这些假设对本文所研究的基准而言是自然的，但在**会话边界更不清晰**、或**交互结构更开放**的场景中可能需要改造。

## 8. Ethics Statement / 伦理声明（全文）

**EN.** This work studies long-horizon memory management for LLM agents. All experiments are conducted on the publicly available benchmark, which consists of synthetic conversations and does not contain real user data.   - **A.1 记忆增强 LLM agent**：现有工作沿三个层面展开——**架构层**（Generative Agents 的时序记忆流、MemGPT 的分层虚拟内存、MemoryBank 的遗忘曲线、SG-Mem/Memoria 的图结构）、**组织层**（Mem0 抽取整合、A-Mem 的 Zettelkasten 互链笔记、LightMem 的轻量多阶段、SimpleMem 的语义无损压缩、EverMemOS 的自组织记忆 OS）、**检索层**（Zep 的时序知识图、MemR³ 的闭环检索控制器）。这些方法主要**孤立优化**记忆流水线的单个阶段；MemMA 的对比面更广：它沿前向协同构建与检索，并把利用失败转成后向对记忆库的直接修复信号。
  - **A.2 自演化与反思**：按"改什么"分四级——**output 层**（Self-Refine、Reflexion、TESSA，改模型输出，不改记忆库）、**experience 层**（ExpeL、Voyager、O-Mem，把知识累积在辅助存储/技能库，不修主记忆库）、**policy 层**（MemRL、Mem-α、Mem1 等，训练更强的记忆策略或用 RL 优化记忆整合）、**memory-bank 层**（MemBuilder 合成 QA 当密集奖励）。**MemMA 位于 memory-bank 层**：它**直接修复记忆库本身**，且**不做梯度训练、也不需分离的经验存储**。
- **附录 B（动机分析细节）**：B.1 三档基线实现（Static 用单 agent 流水线 + 一次性 top-30 余弦检索；Unguided Active 加查询改写模块；Strategic Active 再加 planner 提供构造与检索的显式指导）。B.2 四个案例：
  - **Case 1（Aimless Retrieval / 词面复读死循环）**：问"When did Melanie go to the museum?"（gold: 5 July 2023）。Static 完全没检索到；Unguided Active 连做 5 轮改写，但都在原句附近打转，检索漂到 park/beach/camping；Strategic Active 直接指出"缺的是日期"，并发现证据中其实已有答案——**问题不在这轮改写次数，而在能否诊断出缺失的具体属性**。
  - **Case 2（事件歧义需消歧而非扩搜）**：问"When is Caroline going to the transgender conference?"。Unguided 的改写越来越泛，混进一批过去的 LGBTQ 事件；Strategic Active 把缺口收窄成两点——**未来 vs 过去**、**transgender conference vs LGBTQ conference 可能指不同事件**。
  - **Case 3（Myopic Construction）**：Static 把一句问候当成独立条目存下，又把整个 support-group 情节反复追加到一条**过度膨胀**的记忆里，结果记忆库混入低价值填充、且同一情节散落在多条重叠条目中。Strategic Active 的 planner 会标记重要性/时间语境/冗余，并建议合并相似记忆——**但最终记忆仍把同一情节分散在若干重叠条目里**，因为 planner 指导只是"建议"，而 Memory Manager 仍是一次处理一句的原子编辑。**洞察：Myopic Construction 不只是"缺 planner"，逐条编辑的局部策略本身就会产生碎片化，因为 Memory Manager 无法在单次编辑里做全局重组。**
  - **Case 4（planner 指导是建议而非约束）**：问"What activities does Melanie partake in?"（gold: pottery, camping, painting, swimming）。**Unguided Active 答对，而 Strategic Active 答错**。planner 的指导本身合理（提醒覆盖多类活动），但 Query Reasoner 判了 ANSWERABLE 就提前停、Answer Agent 又从偏斜的证据子集里选，漏掉 gold 项。**洞察：指导若不被下游当成约束执行，高层推理再对也会失败——这正是 MemMA 要加强协调的动机。**
- **附录 C/D/E（提示词）**：C 给出 Meta-Thinker 的构造指导与可答性检查 prompt；D 给出 Query Reasoner 的改写 prompt；E 给出就地自演化的三类探针（单跳事实 / 多会话推理 / 时间推理，Table 8 有示例）、证据锚定修复 prompt、语义整合 prompt。**MemMA 的"方法"几乎全部沉淀在这 7 张 prompt 模板里。**

- **附录 G（探针生成模型的影响）**：Table 9 见上文"关键实验"节。结论：**Opus 综合最好**（76.97 ACC / 45.10 F1）；Haiku 与 Sonnet **ACC 相同**（74.34）但词面指标分叉（Haiku 44.98/35.69 vs Sonnet 43.30/32.74）。原因是**探针风格**：Sonnet 探针过短（均长 11.12 词，380 条里 136 条 ≤3 词，单跳题 64/95），只测"关键词在不在"；Haiku（19.43 词）与 Opus（21.48 词）把更多探针分配给多跳/跨会话关系题，因此修复质量更强。论文强调这不是幻觉问题，而是**过度压缩导致信息丢失**。
- **附录 H（案例研究全文）**：H.1 前向路径的**构建期指导**——MemMA_SA 答出 "rainbow sidewalk" 这一物体级细节，去掉指导的 MemMA_SA/C 给出含混的 "cool stuff" 并把散步与骑车混淆；另一例中指导还**阻止了破坏性合并**（把 clarinet 与 violin 合成一条冲突条目）。**结论：构建期指导在信息进入记忆之初就保住承载答案的细节，迭代检索无法找回从未存下的东西。** H.2 前向路径的**迭代检索**——"时间锚点"类恢复（先查家乡、再追问国家名，最终答出 "Sweden"）；"缺失事件细节"类恢复（把泛泛的 "amazing views" 细化为 "Perseid meteor shower"）。**结论：前向路径的改进不是因为答得更好，而是因为推迟作答、直到取回时间锚点。** H.3 后向路径的**就地自演化**——三类可迁移修复：(i) **命名实体插入**（补出 "Matt Patterson"；修复直接迁移到下游题 "What musical artists/bands has Melanie seen?"）(ii) **区分性事件细节锐化**（把泛泛的露营回忆锐化成 "Perseid meteor shower"）(iii) **部分证据簇补全**（把含糊的 "pots" 补成"带狗脸的杯子、彩碗、黑白碗"，使一个稀疏的证据簇整体变得可答）。**要点：探针失败不被留在原地，而是转成证据锚定的修复动作，直接迁移到下游基准表现。**
