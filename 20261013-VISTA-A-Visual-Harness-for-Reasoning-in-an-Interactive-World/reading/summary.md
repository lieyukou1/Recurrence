## 一句话总结

VISTA 是一个**视觉原生（vision-native）的 agent harness**：它让通用多模态模型**直接看原始图像**（而非文本网格），并外挂一个**无损视觉记忆 + 主动视觉检查**机制来对抗上下文压缩造成的信息丢失；结果在 ARC-AGI-3 上把 Claude Opus 5.0 的 RHAE 从 40.68 提到**满分 100.00**，动作数比首次游玩人类还少 57.4%。核心主张是：**能力本来就在模型里，harness 只是把它"引"出来**。

---

## 研究动机与问题

- **要解决的问题**：AI 能否像人一样，在**陌生、动态、高维**的环境里，靠"看 + 推理 + 行动"搞懂世界规则并达成目标？（§1，p.1）
- **已有方法的不足**（p.1–3）：
  - ARC-AGI-3 传统上被当作**语言问题**处理：把环境压成文本/符号表示，再让 LLM 用代码搭一个"可执行世界模型"（program synthesis）。当环境越来越**视觉化**（状态转移、目标条件难以用符号程序表达），这条路越来越吃力。
  - 现有 VLM 范式（Fig.1b）：把每张图**一次性编码**成视觉表征。这些表征**可能有损、被压缩**，不足以支撑后续推理；而且早期观测会因上下文限制被**移除或替换成文本摘要**——长程交互中信息持续丢失。
- **论文的切入点**：把 ARC-AGI-3 **reframe 成视觉问题**——所见即所得地喂原始 PNG，并把"记忆"从模型上下文里**外置**到一个无损存档中，让模型**主动**决定回看什么、放大哪里（Fig.1c）。

## 核心思想

一句话：**别让模型把世界"读一遍就丢"，给它一个可以随时翻回去的完整视觉档案。**

三个设计（§3.1，Fig.3，p.3–4）：

1. **Visual observation（视觉观测）**：直接给渲染后的原始图像。论文里 agent 收到的是 512×512 PNG，由官方 64×64 帧做 **8× 最近邻上采样**并加一格网格线得到（§4.3，p.6）。**关键：agent 从不知道"世界是 64×64 网格"**，它只看到图像，靠视觉先验自己理解物体与空间关系。
2. **Lossless visual memory（无损视觉记忆）**：环境返回的**每一帧**（包括动作触发的**中间动画帧**）都以**原始分辨率**存档，按 `turn` 与 `frame` 索引；它独立于模型当前上下文，**不会因为上下文被截断而消失**。
3. **Visual inspection（视觉检查）**：在无损记忆之上，给模型主动"看"的工具——
   - `inspect`：**跨空间**放大任一矩形区域（可放大到全分辨率），或**跨时间**调取任意历史 turn 的多帧；
   - `read_pixels`：读取选定单元格的**精确像素值**；
   - 这些工具是**可选、只读**的；唯一会改变游戏状态（也唯一计入动作数）的是 `play`（§A.4，p.17）。

配套还有**两层笔记**：`GUIDE.md`（跨关卡/跨 session 复用的规则理解）+ `WORKING.md`（当前关卡草稿）；上下文将满时把状态压缩成 handoff summary，然后**在新上下文里带着笔记与动作历史继续跑**（§3.2，p.4）。

作者反复强调定位：**harness 改变的是 agent 对"证据"的访问方式，而不是模型的推理能力本身**（p.3–4）。

## 方法拆解

### 1) 系统结构（§3.2 + §A.4，p.4/p.17）

- 模型与 harness 通过**多轮对话**交互；harness **纯机械**：只执行工具调用（`inspect` / `read_pixels` / `play`），返回图像或像素值，报错非法请求，**不训练任何模型**。
- 全部工具经**结构化函数调用**暴露：Claude Code 走 **MCP server**，Codex 直接注册同名工具。运行在**沙箱容器**内，**无环境凭证访问权**（A.4）。
- 一个**单进程 host-side controller** 持有：环境连接、存档帧、`GUIDE.md`、`WORKING.md`，并且是**唯一**被允许推进游戏状态的组件。
- **强制顺序交互**：新的 `play` 调用只有在前一个动作结果返回后才被接受；每张返回的图像都带 `turn` 与 `frame` 标签。
- **上下文压缩机制**：接近上下文上限时，controller 暂停常规工具使用，要求模型先保存状态——Codex 用 `save_compact_checkpoint`，Claude Code 用 pre-compaction hook 触发 `write_working`；随后在新上下文中带着 `GUIDE.md`/`WORKING.md`/动作历史/当前帧恢复。

### 2) 工具接口（§A.4，p.17，伪代码）

| 工具 | 作用 | 是否改变环境 |
| --- | --- | --- |
| `play(action, x=None, y=None)` | 执行**恰好一个**游戏动作，返回最终帧 | ✅ 唯一改变环境的工具，计入动作数 |
| `inspect(question, views)` | 检索/裁剪/放大任意存档帧，支持 `turn`/`frame`/`region` 组合视图 | ❌ 只读 |
| `read_pixels(question, views)` | 读取选定单元格的像素值（调色板 / 样本） | ❌ 只读 |
| `history(view, start_turn, ...)` | 统计本次尝试的动作/结果记录 | ❌ 只读 |
| `read_guide` / `write_guide` | 读写 `GUIDE.md` | ❌ 只更新笔记 |
| `read_working` / `write_working` | 读写 `WORKING.md` | ❌ 只更新笔记 |
| `save_compact_checkpoint(guide, working_memory)` | 上下文压缩前原子性保存状态 | ❌ 只更新笔记 |

### 3) Prompt（§A.5，p.18）

三个基准共用同一模板，仅替换任务描述与 note 说明：ARC-AGI-3 用 "Visual game task"（**用尽可能少的动作通关**）；GameWorld/AI GameStore 用 "Interactive world task"（把 `play` 换成 `act`）；BabyVision 用更短的 "Visual question task"（因为任务是**单张静态图**，省去持久笔记，但保留 `inspect`/`read_pixels`）。

## 关键公式

详见 [formulas.md](./formulas.md)。核心是 **RHAE**（Relative Human Action Efficiency）：

- 关卡级 $S_{\ell,g}=\min\left(1.15,\ (h_{\ell,g}/a_{\ell,g})^2\right)$（Eq.1，p.16）——人类上中位数动作数 / agent 动作数的平方，封顶 1.15；未完成得 0。
- 游戏级 $S_g$ 取"**加权完成率**"与"**加权关卡得分**"的 min（$w_\ell=\ell$，Eq.2）——既看完成度也看效率。
- 最终 RHAE = 25 个公开游戏的 $S_g$ 平均 ×100。

## 实验与结论

### 设置（§4.1 / §A.1）
- **数据集**：ARC-AGI-3 的 25 个公开游戏，每游戏含多关卡，关卡共享机制但引入新物体/布局/约束。
- **模型**：Claude Opus 5.0（经 Claude Code CLI，xhigh 推理档）与 GPT-5.6 Sol（经 Codex CLI，max 推理档）；另有开源 GLM-5.3 Flash 320B。
- **基线**：官方实现用**文本网格**观测 + 最多保留 7 个中间状态，175K token 上下文，超限丢最早轮次（**无长期记忆**），每局动作上限 2000（Opus/GPT-5.6）、3000（GLM）。

### 主要结果

**① ARC-AGI-3（Table 1，p.5；Table 2，p.20）**

| 系统 | 用程序合成 | 模型 | RHAE |
| --- | --- | --- | --- |
| Official impl. | 否 | GPT-5.6 Sol / Opus 5.0 high | 13.33 / 40.68 |
| Schema [62] | 是 | GPT-5.6 Sol / Opus 4.8→5.0 | 95.35 / 98.98 |
| evmva_sv_x1.6 [39] | 是 | GPT-5.6 Sol | 98.97 |
| Retrodict [11] | 是 | GPT-5.6 Sol | 99.86 |
| Tycho [25] | 是 | Opus 5.0 | 100.00 |
| **VISTA** | **否** | GPT-5.6 Sol / Opus 5.0 | **99.00 / 100.00** |

- Claude Opus 5.0 + VISTA：**RHAE 100.00**，总动作 **7,302**，对比人类参考 17,135 = **少 57.4%**；每个游戏都拿到 100 分（Table 2，比值 0.43×）。
- GPT-5.6 Sol + VISTA：RHAE 99.00，总动作 9,126，比值 0.53×。
- **VISTA 是首个"不用程序合成"就达到完美/近完美**的系统。

**② 组件消融（Fig.5，p.6，GPT-5.6 Sol，200K 上下文）**

官方文本网格 13.33 →（i）换图像观测 47.32 →（ii）放宽动作/时限 51.66 →（iii）连续对话 65.82 →（iv）加 `GUIDE.md`/`WORKING.md` 70.05 →（v）**加无损记忆 + model-directed inspection 94.10** →（vi）**加像素读取 99.00**。
→ 最大的两次跃升正好对应 VISTA 的两个核心组件（(iv)→(v) 与 (v)→(vi)）。

**③ 观测表征对比（Fig.6，p.6）**：文本网格 RHAE 96.75 / 10,614 动作 / **71.9M token/局**；图像观测 99.00 / 9,126 动作 / **30.7M token/局**。→ 性能相当但**图像省一大半 token**（64×64 文本网格约占 4,000 token，而 512×512 图像仅约 308 image token）。

**④ 上下文与分辨率消融（Fig.7，p.7）**
- 上下文：100K→98.6（token 减半）、**200K→99.0（最优）**、500K→94.4、780K→93.9（且 780K 每局烧 105.7M token）。→ **更大的上下文反而更差**。
- 图像尺度：2×→96.6、**4×→99.7**、8×（默认）→99.0、16×→88.3。→ 4× 比默认省约 75% image token 且性能相当；2× 掉点，16× 无收益且更贵。

**⑤ 开源模型（Fig.8，p.7）**：GLM-5.3 Flash 320B——官方实现 1.89，去掉 harness（仅去 `inspect`/`read_pixels`）13.27，**完整 VISTA 66.93**。→ 全开源可复现路线上同样成立。

**⑥ 3D 渲染鲁棒性（Fig.9，p.8）**：同一批游戏改成 3D 渲染——2D：RHAE 99.00 / 9,126 动作；3D：84.12 / 20,640 动作。→ 掉点但**仍大幅优于官方文本基线**。

**⑦ 跨环境泛化（§5，Fig.11，p.9）**

| 基准 | 人类参考 | 官方实现 | VISTA（GPT-5.6 Sol） |
| --- | --- | --- | --- |
| GameWorld（34 游戏/170 任务）成功率 | 55.3%（新手） | 40.0% | **63.3%** |
| GameWorld 进度 | 64.1% | 62.9% | **79.9%** |
| AI GameStore（10 游戏，几何均值，人类中位数=100） | 100 | 47.3 | **140.3** |
| BabyVision（39 题，准确率） | 92.3% | 41.0% | **63.2%**（此前最佳 25.7%） |

→ 迁移几乎不用改 harness；**BabyVision 是静态单图**、无交互历史，仍从 41.0%→63.2%，说明 `inspect` 对**单图内选择性查看区域**同样有效。

**⑧ 稳定性（§B.1，p.19）**：主要实验重复 3 次——ARC-AGI-3 RHAE 99.04 ± 0.17；GameWorld 成功率 63.33 ± 2.37%；BabyVision 63.23 ± 3.00%。

### 定性分析（§4.4 / Fig.10 / Fig.12–14，p.8/p.21–23）
- **跨空间与时间**（Fig.10a）：棋盘 reset 后，模型用**一次** `inspect` 调回前 22 轮的 4 帧，重建地图（"gravity flip 之后地图长什么样"）。
- **局部视觉细节**（Fig.10b）：把三个小方块放大约 **13×**，才能看清哪一面带紫色标记，从而判断每个 block 的朝向。
- Fig.14 给出 ARC-AGI-3 之外的轨迹：Minecraft 中跨空间放大区分铁矿石与圆石；Pac-Man 中跨时间回看完整迷宫；连线题中放大区域 + `read_pixels` 追踪路径；迷宫题 2× 放大 + 读整幅网格像素。

## 局限性

- **论文自述**（§6，p.10）：模型的**既有能力仍是关键因素**，VISTA 只是"引出"它们的方式；所用模型在公开基准发布**之后**才发布，**无法排除这些游戏进入了训练数据**——在**未见过的新游戏**（如 ARC-AGI-3 私有集）上评估才能更强地检验泛化。
- **我读出来的**：
  - harness 的收益高度依赖**强模型 + 其 agentic CLI（Claude Code / Codex）**；换成弱模型能提升多少、是否仍有 66 分级别，只有 GLM-5.3 Flash 一个数据点。
  - **成本没被隐藏但也没被正面比较**：RHAE 只计游戏动作，`inspect`/`read_pixels`/推理调用**不计入**；Fig.5/7 显示 token 消耗可观（每局数千万级）。
  - **"无损记忆"的检索仍是模型自选**：`inspect` 是否被用对、用够，依赖模型的元认知，弱模型可能不会主动回看。
  - 3D 渲染掉点明显（99→84），说明对**非训练分布般的视觉表征**鲁棒性一般。
  - 一些对比（如 Table 1 的官方分数）是**外部报告结果**，非同口径消融（论文自己也承认）。

## 复现要点

- **官方代码**：https://github.com/joshhhhhan/VISTA（README 中给出 Code 链接，p.1）。
- **最有价值的复现目标**：不要冲 100 分，而是复现两个**核心结论**——
  1. "图像观测 > 文本网格"（省 token 且不掉点）；
  2. "无损记忆 + model-directed inspection"是增益主来源（对应 Fig.5 的 (iv)→(v)/(vi)）。
- **最可行的路线**：官方开源代码 + **GLM-5.3 Flash 320B**（全开源、可复现，论文 Fig.8 给出 66.93 的锚点）。若用闭源模型，成本与可及性是主要障碍。
- **环境特点**：需要能跑 Claude Code CLI / Codex CLI 或接入等价 API；沙箱容器；ARC-AGI-3 环境本身需从官方获取（[4] arXiv:2603.24621，benchmark 未公开游戏代码需另外申请）。
- **易踩坑**：
  - RHAE 的计分口径（动作数定义、人类上中位数、加权 $w_\ell=\ell$、封顶 1.15）务必对齐官方 scorer；
  - 图像 512×512 = 官方 64×64 的 **8× 最近邻上采样 + 网格线**，不要自行改成插值缩放（会影响模型可读性）；
  - `play` 一次只执行一个动作、且必须串行；多动作要多次调用；
  - 上下文压缩的 checkpoint 机制要实现，否则长局会崩。

## 我的思考

- **本质贡献是"接口设计"而非新模型**：它把"记忆"从模型上下文（易失、有损、按 token 计费）里**解耦**到一个外置的、可按需检索的存档。这在很多长程视觉任务上都能复用，不限于游戏。
- **对 RAG/Agent 的启示**：相比"把历史总结成文本塞回上下文"，**保留原始模态 + 让模型主动取用**是更保真的做法；`inspect` 之于图像，类似检索之于文本。
- **可疑但值得追的点**：论文坦承模型可能见过这些游戏——**"harness 能引出能力"与"模型记住了游戏"**这两者在公开基准上难以分离；私有集/自造环境是更有意义的验证。
- **可迁移到本工作区**：这套"原图存档 + 主动放大/取帧 + 两层笔记 + 上下文压缩续跑"的 harness 结构，本身就是一份很好的**长程多模态 agent 工程模板**，值得作为一个独立的 reproduction 目标去搭一个最小可跑版本。
